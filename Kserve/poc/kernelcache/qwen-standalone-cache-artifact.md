# POC-3: Qwen Standalone Cache Artifact Verification

### Goal

Verify whether the workload-specific cache artifacts generated by `Qwen/Qwen2.5-0.5B` can be reused independently, without any cache artifacts previously generated by `facebook/opt-125m`.

This test extends the previous Triton-only isolation test by isolating both the vLLM cache and the external Triton cache.

### Test Setup

Two separate PVCs were used:

```text id="r2s0au"
/tmp/vllm   -> VLLM_CACHE_ROOT
/tmp/triton -> TRITON_CACHE_DIR
```

All known OPT-specific artifacts were removed from the cache.

Only the Qwen-specific artifacts were retained.

#### VLLM Cache

```text id="89a8f8"
/tmp/vllm/modelinfos/
└── vllm-model_executor-models-qwen2-Qwen2ForCausalLM.json

/tmp/vllm/torch_compile_cache/
├── 1c3d61805a/
└── torch_aot_compile/
    └── 2e255240773e1183b2e0bf6e294532c36b76dc5251c58e2949ccd9d781bcfca0/
```

#### External Triton Cache

```text id="dh6chv"
/tmp/triton/
└── 21 Qwen-specific Triton cache entries
```

The 30 Triton entries and all known vLLM compile/AOT artifacts previously generated by OPT were excluded.

### Conclusion

The isolated Qwen cache artifacts were sufficient to successfully restore the Qwen compilation state through startup and warmup.

The test demonstrates that the Qwen workload did not require the previously generated OPT artifacts from either:

* `VLLM_CACHE_ROOT`
* `TRITON_CACHE_DIR`

The resulting workload-specific cache boundary can therefore be represented as:

```text id="4ogfwi"
Qwen Cache Artifact
├── modelinfo
├── vLLM compile-cache entry
├── AOT compile artifact
└── Triton cache entries
```

This provides strong evidence that GKM can capture a **workload-specific cache delta** instead of packaging the entire shared vLLM/Triton cache directories.

Conceptually:

```text id="87a25f"
Shared Cache Before Workload
          │
          │ Run Qwen
          ▼
Shared Cache After Workload
          │
          │ Compute Delta
          ▼
┌─────────────────────────────┐
│ Qwen-specific Cache Artifact│
│                             │
│ • modelinfo                 │
│ • compile cache             │
│ • AOT artifact              │
│ • Triton kernels            │
└──────────────┬──────────────┘
               │
               │ Restore on clean runtime
               ▼
        Qwen AOT Cache HIT
```

### Remaining Verification

Startup and warmup have been verified.

As a final validation, an actual inference request should be executed and the cache directories checked afterward to confirm that:

1. inference succeeds,
2. no JIT compilation warning is emitted,
3. the Triton cache remains at 21 entries, and
4. no additional vLLM compile/AOT cache hashes are generated.

If those conditions hold, the Qwen-specific cache delta can be considered self-contained for the tested workload and runtime configuration.
